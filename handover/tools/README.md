# 언어 축 도구 한 벌

「본체 언어 설정을 바꿔 가며 화면을 대조한다」에 쓰는 것들.
한패공방(메탈슬러그 2nd 방)에서 만들어 쓰던 것을 그대로 옮겼다.

    ngp_langdiff.py        언어 축 픽셀 대조 — **자기가 잴 수 있는지 먼저 잰다**
    ngprun.c               하네스. NGP_LANG 환경변수를 코어에 넘긴다
    ngp_settings_guard.py  패치가 본체 설정 램(0x6F87)을 건드리는지 동적 검사
    sheet.py               PPM 여러 장을 한 판 PNG 로 (눈으로 훑을 때)

## ★ 하네스를 먼저 빌드하라 — 이게 전부다

    gcc -O2 -o ngprun ngprun.c -ldl

**같은 이름의 옛 빌드가 기계에 여러 벌 있을 수 있다.** `NGP_LANG` 을 안 읽는
빌드로 돌리면 두 판이 당연히 같고 「다름 0 = 통과」라는 **가짜**가 나온다.
실제로 그럴 뻔했고, 그래서 도구가 스스로 재게 고쳤다.

    맞는 하네스   →  「같음 n · 다름 m」 을 낸다
    틀린 하네스   →  ✗ 하네스가 NGP_LANG 을 안 넘긴다 … 이 판정은 가짜다

곧 **결과가 나오면 자는 맞은 것**이다. 대조군을 사람이 기억하지 않아도 된다.

## 쓰기

    ./ngp_langdiff.py <ngprun> <core.so> <롬> <대본> [작업폴더]

대본은 「<프레임> <버튼…>」 과 「!<태그>」 로 된 줄들이다. 짧아도 된다.

    600 / 2 B / 200 / !a / 2 ST / 200 / !b / 2 B / 250 / !c

## ★ 검출력 대조군은 여전히 사람 몫이다

도구는 **하네스가 축을 넘겼는지**를 잰다. 그러나 **그 화면이 언어를 쓰는지**는
못 잰다. 어트랙트 화면처럼 언어를 안 쓰는 무대에서는 원본도 「다름 0」이 나온다.

    반드시 **순정 롬으로 먼저** 돌려 다름 > 0 이 나오는지 보라.
    안 나오면 그 대본은 그 게임을 판정할 수 없다 — 대본을 더 밀어야 한다.

## ★ 롬이 순정인지 해시로 확인하라

작업 폴더의 롬은 이미 패치본인 경우가 많다. 여덟 게임을 훑을 때 넷이
순정이 아니었고 그중 하나는 아예 옛 한패본이었다. `[!]` 덤프의 crc32 를 먼저 봐라.

## 고칠 때

비교(`CP`, 읽기 전용)는 **건드리지 말고 분기만** 고정한다. `AND` 로 바꾸면
램에 되써서 **유저 본체 설정을 덮는다**(실기에서 배터리 백업이면 되돌리기도
어렵다). TLCS-900 은 조건코드 0=F(절대 아님), 8=T(늘).

    JR  Z  (66) → JR  T (68)     JR  NZ (6E) → JR  F (60)
    JRL Z  (76) → JRL T (78)     JRL NZ (7E) → JRL F (70)
    JP  NZ (DE) → JP  F (D0)     RET Z (B0 F6) → RET T (B0 F8)

고친 뒤 `ngp_settings_guard.py` 로 **램을 안 건드렸는지 동적으로** 확인하라.
그 도구도 결과를 내기 전에 **일부러 고장을 심어 스스로 잡히는지** 본다.
