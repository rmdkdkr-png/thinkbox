## WSL·셸

- **/tmp 는 Bash 호출 사이에 증발** (WSL VM 유휴 종료) — 호출을 넘겨 쓸 파일은 ~/ 나 /mnt/c.
- **인라인 셸 변수·루프 변수(`$i`, `$f`)는 도구 경유 호출에서 증발** — 명령은 반드시
  **스크립트 파일로 저장 후** `wsl -e bash <파일>` 로. 히어독·유니코드·백슬래시도 동일.
- **PowerShell 을 거친 히어독은 소리 없이 빈 결과**를 낳기도 한다 — 위와 같은 처방.
- **NGPC 롬셋 7z 는 WSL tar 로 못 연다** — Windows `tar.exe`(bsdtar)로 풀 것.
- **파이썬 `"a" + "b %s" % x` 는 마지막 조각만 포맷된다** (% 가 + 보다 우선) —
  긴 문자열 연결에 % 포맷을 섞으면 조각별로 괄호를 쳐라.

- **릴리즈 자산을 크기로 비교해 교체를 건너뛰지 마라** — 번역만 바뀐 같은 크기 판을

- **배포 후 내용이 바뀌면 판번호를 올려라** — 같은 이름 덮어쓰기는 받은 사람과
  본문 해시가 어긋난다 (실제 제보).

- **하네스가 코어 옵션 기본값을 다 안 주면 화면 크기가 조용히 바뀐다.** RetroArch 없이
  코어를 직접 로드하는 하네스(`ngprun`·`svcrun`)는 옵션을 스스로 먹여야 하는데,
  **빠뜨린 옵션의 처리가 코어마다 다르다.** 대부분은 `if (조회성공 && var.value)` 라
  안 주면 무해한데 지오메트리 옵션 둘이 예외다 —
  `ngp_svcsp_band` 는 조회 실패 시 `int on = 1` 로 **켠다**(높이 152→184),
  `ngp_ss2sp_sides` 는 코어 초기값이 `true` 라 안 주면 켜진 채다(폭 160→288).
  그래서 순정 코어는 `160x152`, SP 코어는 `288x184` 를 뱉고 **PPM 바이트 비교가
  조용히 어긋난다.** 크기가 다른 걸 보고도 「디버그 빌드라 그런가」 하고 지나간 전과.
  → 하네스 DEFAULTS 는 **코어가 실제로 읽는 키 전체**와 대조해서 채워라:
  `grep -o '"ngp_[a-z0-9_]*"' libretro.c | sort -u` 로 뽑아 빠진 것을 찾는다.
  (`ngprun` 은 8개만 주고 있었고 그중 하나는 코어가 읽지도 않는 죽은 키였다.)

- **★ `ss2-sp-core/build.sh` 는 커밋 안 된 `build/` 편집을 조용히 버린다 — 그리고 재생성기는 "OK" 라고 찍는다.**
  `build/` 는 **독립 git 레포가 아니라** ss2-sp-core 에 속한 디렉터리다. 그래서 build.sh 의
  `git -C build reset --hard <upstream커밋>` 은 그 커밋이 상위 레포에 없어 **실패하고**,
  `|| git -C build checkout -- .` 로 넘어가 **build/ 를 상위 레포 HEAD 로 되돌린다.**
  이어지는 `git apply --3way src/ss2sp.patch` 는 이미 패치된 파일에 걸려 **no-op** 이 되므로,
  패치 파일에는 내 수정이 들어 있는데 **빌드된 .so 에는 안 들어간다.**
  `regen_patch.sh` 는 왕복 검증까지 통과해 「ss2sp.patch 갱신 OK」를 찍기 때문에
  **성공한 줄 알고 넘어가게 된다.** (실제로 그렇게 한 번 속았다 — 빌드 로그도 정상이었다.)
  → **`build/` 를 고쳤으면 `build.sh` 를 돌리기 전에 커밋해라.** 순서가 규칙이다:
  `build/ 편집 → regen_patch.sh → **커밋** → build.sh`.
  빌드 뒤 `grep <내가 넣은 심볼> build/libretro.c` 로 살아남았는지 한 번 확인하면 확실하다.

- **작업트리를 여러 방이 동시에 쓰면 남의 커밋에 내 변경이 딸려 간다.**
  같은 기계의 같은 체크아웃에서 두 방이 일하면, 한쪽의 `git add`/`git commit` 이
  **다른 쪽의 미커밋 변경을 함께 커밋한다.** 실제로 한 방의 `build/libretro.c` 수정이
  다른 방의 「오버레이 메뉴 롬별 분리」 커밋에 통째로 들어갔다(내용은 맞았으니 사고로 끝났을 뿐).
  → 남의 레포 디렉터리를 건드렸으면 **곧바로 커밋하고, 무엇을 왜 만졌는지 그 방에 알려라.**
  커밋 전 `git status --short` 로 **내가 안 만진 파일이 섞여 있는지** 먼저 봐라.

- **★ 시드(초기 문서 생성) 스크립트를 두 번 돌리면 그 사이 기여가 조용히 사라진다 — 그리고 「강제 푸시」로 오진하게 된다.**
  이 저장소에서 실제로 났다. `knowledge/traps.md` 가 **시드 커밋으로 두 번** 만들어졌다:
  `a9d4fe5`(1차, 3,450B) → `c77c1e9`(다른 방이 「롬 한글화」 절 추가, 7,286B) →
  … → **`29e89a7`(2차 시드, 다시 3,450B)** → 그 뒤 커밋들이 그 위에 쌓였다.
  즉 2차 시드가 파일을 통째로 덮어써 c77c1e9 의 기여가 없어졌다.
  * **커밋은 하나도 안 없어졌다.** `c77c1e9` 는 지금도 main 의 조상이다
    (`compare/c77c1e9...main` → `behind_by 0`, 부모 사슬 14번째).
    **없어진 것은 파일 내용뿐**이다.
  * 그래서 오진이 쉽다 — 「내 절이 없다 + 이력에서 안 보인다」를 보고 force-push 를 의심하게 된다.
    이력에서 안 보인 것은 **API 로 커밋을 12개만 받아서**였다. 그 커밋은 14번째에 있었다.
  * 뒤에 온 사람은 **덮인 판 위에 이어서 쓰게 된다.** 실제로 그랬다(3,450B 에서 이어 붙였다).
  → **시드 스크립트는 파일이 이미 있으면 건너뛰게 만들어라.** 덮어쓰기가 기본이면 안 된다.
  → 원인 진단은 이력 목록의 길이로 하지 말고 **도달 가능성**으로 해라:
  `compare/<sha>...main` 의 `behind_by 0` 이면 그 커밋은 조상이다. 목록은 페이지에서 잘린다.
  → 내용이 언제 사라졌는지는 **커밋별로 파일을 받아 크기를 훑으면** 한눈에 보인다
  (`contents/<path>?ref=<sha>`). 같은 크기로 되돌아간 지점이 범인이다.

  패치/코어로 저장하는 사고 방지.

## 롬 한글화 (그래픽·글리프)

*(한패 방, 2026-09-02 — 메탈슬러그 1st·2nd, 아랑전설, KOF R-2 에서 실제로 당한 것)*

- **덮어쓸 타일이 다른 데서도 쓰이는지 먼저 조사하라.** 메탈슬러그 1st SET UP 은
  라벨과 **값이 같은 글자 타일 풀**(`0x018~0x028`)을 나눠 쓴다. 라벨을 한글로 덮었더니
  `A: SHOT` 이 「설정 SHOT」, `◀9▶` 가 「나9나」로 깨졌다. 아랑전설의 「영문 글리프는
  스프라이트가 쓴다」, KOF R-2 의 글리프 공유와 **같은 사고**다.
  처방: 타일맵을 통째로 읽어 **내가 안 바꾸는 칸이 쓰는 타일**을 모으고 거기 없는
  칸만 배정한다. 모자라면 **거부**하고 낱말을 줄여라 (「나가기」→「종료」).
- **화면에 안 나오는 글자는 쓴 게 아니다.** 메탈슬러그 1st 브리핑은 페이지가 8자 폭인데
  화면엔 **줄마다 정해진 칸수만** 깔린다(7/7/7, 4/8/7/7 …). 넘긴 글자는 롬에도 char RAM
  에도 실리는데 타일맵에 안 깔려 조용히 사라진다 — 세 장이 전부 끝 글자가 잘린 채
  나갔다. 겉모습이 「안 구워졌다」와 똑같아 엉뚱한 데를 뒤지게 된다.
  처방: **원본 롬과 한글 롬의 타일맵을 비교**해 폭이 데이터가 아니라 표에서 나오는지
  확인하고, 잰 폭을 빌더에 한계로 박아 넘치면 거부.
- **같은 낱말 타일이 롬에 여러 벌 있다.** 메탈슬러그 1st 게임오버의 `RETRY` 2벌,
  `SAVE` 4벌, `END` 2벌. 화면마다 다른 뭉치를 싣기 때문에 한 주소만 고치면
  어떤 화면은 영문이 남는다. 처방: 주소를 박지 말고 **원본 타일 바이트와 똑같은 자리를
  전부 찾아** 갈아 끼운다 (64바이트짜리 글자 그림이 우연히 겹칠 일은 없다).
- **정적 분석이 두세 번 어긋나면 화면을 떠라.** 메탈슬러그 2nd 글꼴은 정적으로는
  「32타일 폭 띠」로 보였고 어떤 정렬로 그려도 글자가 겹쳤다. VRAM 한 장으로
  「한 글자 = 연속 4타일(좌상·우상·좌하·우하)」이 바로 나왔다. 1st 의 페이지 주소도
  같은 방법으로 풀었다. **화면 → char RAM → 롬 역추적**이 제일 빠른 길이다.
- **값을 몰라도 «차이»로 롬을 찾을 수 있다.** 메탈슬러그 2nd 대사 코드열을 찾을 때,
  화면에서 읽은 글자 순서를 **인덱스 차이**로 바꿔 훑었다. 기준값을 몰라도 차이는
  기준과 무관해서 4MB 에서 한 곳만 걸렸고, 덤으로 글리프 표 기준까지 확정됐다.
- **훑기 끝점을 한 종류로 못 박지 마라.** 코드열 끝 제어코드가 뭉치마다 다르다.
  한 종류로 박으면 뭉치를 놓치고, 마지막 제어코드까지 무조건 끌고 가면 표 앞부분을
  코드로 잘못 읽어 또 놓친다. 제어코드 자리를 **전부 후보로 놓고 조건을 통과하는
  가장 긴 것**을 고를 것. 후보마다 다시 훑으면 O(n²) 라 4MB 에서 안 끝난다 —
  앞에서 한 번만 훑으며 판정하면 O(n) (10분 초과 → 0.4초).
- **훑는 도구의 시작 홀짝을 고정하지 마라.** 메탈슬러그 2nd 의 대사 뭉치를 찾는
  훑기를 `i = 0` 에서 `i += 2` 로 짰더니 **짝수 주소만** 봤다. 마침 짝수였던 두 뭉치는
  걸리고 홀수였던 두 뭉치는 통째로 안 보였는데, 그걸 모르고 「롬 전체에 두 뭉치뿐」
  이라는 **결론까지 냈다**. 도구의 빈틈을 데이터의 성질로 읽는 게 이 사고의 본질이다.
  u16 을 훑으면 홀짝 둘 다 돌려라. 「전부 찾았다」는 도구가 못 볼 자리를 따진 뒤에.
- **같은 글리프가 표 여러 곳에 있으면 표마다 다 계산해 보라.** 메탈슬러그 2nd 는
  같은 글자 그림이 표 세 곳에 있다. 화면에서 뜬 글리프의 롬 주소를 «어느 표» 기준으로
  인덱스로 바꾸느냐에 따라 값이 완전히 달라진다. 한 표 기준으로 못 찾았다고
  「인덱스 방식이 아니다」로 넘어갈 뻔했다 — 실제로는 옆 표 기준이 맞았다.
- **8×8 칸에 획 많은 한글은 뭉갠다.** 7×7 글꼴에서 연↔련은 64픽셀 중 12픽셀,
  자↔짜는 17픽셀 차이다. 검수자가 오독한 전력이 있다. 8×8 자리에는 **획이 단순한
  낱말**을 골라라 (「종료」→「끝내기」, 「재시도」→「다시하기」).

- **★ 문자열 구역의 「끝」을 넘겨 쓰면 그 뒤는 다른 자료다 — 그리고 화면엔 안 보인다.**
  KOF R-2 v0.2 를 내고 「소리가 안 난다」는 제보를 받았다. 원인은 **10바이트**였다.
  문자열 표가 `0x1D4E22` 에서 끝나는데 그 뒤 네 자리를 「아직 안 옮긴 일본어」로 보고
  덮어썼고, 그 자리는 **사운드 자료**였다. 넷 중 **하나만 건드려도 소리가 통째로 죽는다.**
  * 왜 속았나 — 원본 바이트가 전부 **가나 대역(0xA1~0xDF)** 이라 글자처럼 보였다.
    「가나처럼 생겼다」는 문자열의 증거가 **아니다.**
  * 왜 못 잡았나 — **화면에 아무 영향이 없다.** 고친 판과 깨진 판의 메뉴 순회 화면이
    `.ppm` 바이트 단위로 **완전히 같았다.** 검증이 전부 화면 기준이면 영원히 안 걸린다.
  * 문자열의 진짜 지문: **0x00 종단이 있다 / 모드바이트를 낀다 / 앞뒤로 다른 문자열이 이어진다.**
    구역의 **마지막 레코드**를 늘 따로 의심하라 — 사고는 항상 끝에서 난다.
  * 빌더에 주소 상한(`NOTEXT_FROM`)을 상수로 박아 재발을 막았다. 빌더와 검증기가
    **같은 상수**를 봐야 한다.

- **소리는 소리로 재라 — 화면 검증은 소리 회귀를 못 잡는다.**
  위 사고 뒤 하네스(`ngprun`)에 **음량 계측**을 넣었다. 코어가 주는 샘플의 절대값 합·
  최대 진폭·「소리 난 프레임 수」를 대본 끝에 찍는다. 그러면 판정이 숫자가 되고
  이분법에 그대로 쓸 수 있다 — 원본 최대 6910 / 깨진 판 **0**.
  IPS 구역 24개를 하나씩 발라 범인을 찾는 데 몇 분이면 됐다.
  **판정식 대조군을 먼저 세운 덕이다**: 「아무것도 안 바르면 소리가 나야 하고
  전부 바르면 죽어야 한다」를 통과한 뒤에야 탐색을 시작했다.
  → 롬을 고치는 모든 방은 **화면·소리·입력**을 각각 숫자로 재는 자를 갖춰라.
  안 재는 축은 안 고쳐지는 축이 아니라 **안 보이는 축**이다.
