# NGP(C) SNK 그림 아이템 — 타이틀 로고를 «그대로» 갈아 끼우는 법 (1-f7, 2026-09-05)

처음 보는 사람 기준. 메탈슬러그·카드파이터즈 등 다른 NGP 게임에서 같은 일을 할 때 이 문서와 `tools/logo_tool.py` 만 있으면 된다.
SS2 타이틀 로고(순정 0x0837B3)와 월화(UE) 타이틀 로고(0x088200)에서 확인했다. 게임마다 «아이템 머리»만 새로 찾는다.

## 1. 한 줄

큰 그림(타이틀 로고·카드 제목·이름판)은 «압축»이 아니라 **그림 아이템**이다: 타일 목록 + 칸마다 (타일, 팔레트) 2바이트 지도.
지도에 팔레트가 적혀 있으니 **팔레트를 화면에서 잴 필요가 없고**, 타일 자리가 칸 수보다 많으니 **타일을 합칠(=뭉갤) 이유가 없다**.
규칙을 지킨 PNG 는 픽셀 그대로 들어간다(SS2 한패 로고 왕복 화면 0바이트 차이).

## 2. 문법

    cnt16 | ptr32 | off16 × cnt | 헤더 1B | 행 × [ 칸 × (타일, 팔레트바이트) ] + ff ff

| 필드 | 뜻 |
|---|---|
| cnt16 | 이 아이템이 문자RAM 에 싣는 타일 수 |
| ptr32 | 타일 기준 CPU 주소 (파일 오프셋 = CPU − 0x200000). 여러 아이템이 한 뱅크를 나눠 쓴다 |
| off16×cnt | 타일 i 의 위치 = ptr + off[i]. 16 B 단위(8×8, 2bpp) |
| 헤더 1B | 0x8B 등. 게임·그림마다 다르다(0x86~0x8B 관측). 그대로 둔다 |
| 행 | 칸마다 2바이트: **타일 = 아이템 안 색인(0..cnt−1)**, **팔레트바이트 = (팔레트 − pal_base)×2, 비트7 좌우반전, 비트6 상하반전**. 행 끝 `ff ff` |

- 화면 문자RAM 색인 = 타일 + **tile_base**, 팔레트 = 팔레트바이트/2 + **pal_base**. 두 기준값은 아이템 안에 없다(호출자가 정한다). SS2 로고 128/4, 월화 로고 16/0.
- 순정 지도의 팔레트 값에 비트13(값 16~31)이 섞여 있어도 화면은 하위 4비트만 본다(SS2·월화 화면으로 확인).
- 타일 16 B: 행마다 워드 LE — **둘째 바이트가 왼쪽 4px**, 픽셀 x 의 값 = 워드 비트(15−2x, 14−2x) «MSB 먼저»(2bpp, 값 0 = 투명/배경). 월화 화면에 반쪽 타일 0x55AA 를 넣어 실측(왼쪽 = 색1, 오른쪽 = 색2). 대칭 시험 패턴은 이 순서를 못 잡는다 → 비대칭으로.
- 팔레트: 워드 = b<<8 | g<<4 | r (4비트씩). 스크롤1 팔레트는 VRAM 0x8280~0x82FF(16개×4색). 롬에 16개 한 덩이로 있는 게임(SS2 0x059188)도, 흩어져 있는 게임(월화: 0x059CF4 여섯 + 0x05A124…)도 있다 → 롬 표를 못 찾으면 **SP 코어 `!vram` 의 .pal 덤프**를 그대로 쓴다.

## 3. 아이템 머리 찾는 법 (게임마다 한 번)

1. SP 코어(ss2-sp-core) `ngprun` 으로 타이틀 화면에서 `!vram t` → `.char`(문자RAM 512장) `.scroll`(평면1·2 지도 32×32 워드) `.pal` `.sprite`.
   ⚠ 순정 코어의 `.ram` 은 작업 RAM 이다. VRAM 아님.
2. 지도에서 로고 행의 타일 색인열을 얻는다(워드 하위 9비트). 팔레트는 비트 9~13.
3. 롬에서 **stride 2** 로 그 열을 찾는다: 색인에서 k(=tile_base 후보 0..400)를 뺀 바이트열이 짝수 위치에 연속으로 나오면 그 자리가 지도 행이다. 행 간격이 (칸수×2+2)면 확정.
4. 첫 행 바로 앞 1바이트가 헤더, 그 앞이 off16 열, 그 앞이 ptr32·cnt16. cnt 는 `(헤더위치 − 6 − 시작)/2` 가 정수로 딱 맞는 시작점을 뒤로 걸어가며 찾는다(`parse_back`).
5. 같은 ptr32 를 가진 다른 기록을 찾으면 «뱅크를 나눠 쓰는 형제 아이템»이다(다른 언어판·리본·인트로 변형). **한 벌만 갈면 다른 벌에서 원문이 튀어나온다**(사쇼1 교훈) — 언어 잠금이 된 한패라면 죽은 벌은 자리로 쓴다.
6. 팔레트바이트/2 와 VRAM 팔레트의 차 = pal_base. 문자RAM 색인 − 지도 타일값 = tile_base.

## 4. 예산 (이게 «압축 노이즈»의 정체)

    칸 수(행×열)  ≤  타일 색인 한도 256  ≤  타일 뱅크 자리(형제 아이템과 나눔)

- SS2 로고: 칸 220, 일본어 아이템 cnt 151, 영어 159, 뱅크 258장 → 칸마다 고유 타일이 가능. 한패가 언어를 잠갔으면 **영어 아이템 자리(기록 + 타일)**까지 먹어 cnt 258 로 키울 수 있고 렌더러는 cnt 를 그대로 따른다(영어 로고 160장을 일본어 자리에 넣어 로고 띠 0바이트 차이).
- 예산이 칸 수보다 작으면 그때만 «같은 8×8 칸은 같은 타일»로 아낀다. 닮은 타일 강제 병합은 하지 않는다(획이 무너진다).

## 5. 도구 `tools/logo_tool.py`

프로파일(JSON, 게임마다 하나):

    {"item":"0837B3", "bank":"083DC9", "bank_end":"084DE9", "pal_tbl":"059188", "pal_base":4, "tile_base":128, "grow_limit":"083DC9"}
    {"item":"088200", "bank":"089E60", "bank_end":"08A7D0", "pal_dump":".../lbt.pal", "pal_dump_off":"80", "pal_base":0, "tile_base":16}

    python3 logo_tool.py extract <롬> <프로파일> <out.png> [배율]     → 원본 PNG(팔레트 색 그대로)
    python3 logo_tool.py build   <롬> <프로파일> <in.png> <출력롬> [grow_cnt]

- build 규칙: PNG 크기 = 칸×8 × 행×8, 팔레트 표에 있는 색만, **8×8 칸 하나에 팔레트 하나**. 어긴 칸은 좌표를 대며 멈춘다(합치지 않는다).
- bank/bank_end = 새 타일을 쓸 자리. 형제 아이템과 뱅크를 나눠 쓰면 «로고만 쓰는 구간»(다른 아이템이 참조하지 않는 오프셋)으로 잡는다.
- grow_cnt: cnt 를 키울 때 아이템 기록이 뒤 자리를 먹는다. grow_limit(뒤 아이템/뱅크 시작)까지만.
- 검증은 «자연 부팅 화면 대조»로(세이브스테이트는 옛 VRAM 을 복원한다). 왕복(extract→build→화면 0바이트)부터 통과시키고 새 그림을 넣는다.

## 6. 디자이너 브리프 표준

`briefs/로고_브리프_표준.md`(SS2 것을 표준으로 둠). 게임마다 바꾸는 것: 캔버스 크기(칸×8), 팔레트 표(색 값), 문구, 참고 PNG. 규칙은 늘 같다 — «팔레트 색만, 칸당 팔레트 하나, 예산 걱정 없음».

## 8. 형식이 다른 게임 — 격자형(B)·원시형(C)

같은 SNK 라도 로고 저장 꼴이 셋이다. 게임마다 먼저 형식을 가른다(`find_item.py` 가 A 형을 못 찾으면 아래 표).

| 형식 | 기록 | 타일 | 도구 | 게임 |
|---|---|---|---|---|
| A 아이템형 | §2 | 오프셋표(자유 배치) | logo_tool.py | SS2 · 월화 |
| B 격자형 | `W8 H8 \| ptr32 \| cnt16 \| u16×5 \| W×H×(타일,팔)` 행 구분 없음 | ptr 부터 «연속» cnt 장 | grid_tool.py(추출) · **grid_build2.py(최소변경 삽입)** | KOF R-2(두 겹) · SvC |
| C 원시형 | VRAM 워드 그대로 W×H | 색인 순 연속 base+16·idx | raw_tool.py | 아랑 FC |

- B 형 지도는 «기록 cnt 밖 색인»(다른 그림이 실어 둔 타일)도 참조한다. 색인을 다시 매기면 다른 화면 요소가 깨진다(R-2 379칸·SvC 43칸). → **바뀐 칸만** 새 타일로(grid_build2), 예산 = cnt 중 «바뀐 칸만 쓰던 색인». 구멍 시험(16×16 지움)으로 화면이 딱 4칸만 바뀌는지 본다.
- B 형 머리 찾기: 롬에서 `14 13`(20×19) 같은 W H 바이트 뒤 ptr32 가 롬 범위인 곳을 모아, 지도(+18)를 VRAM 평면과 «행·열 오프셋·k» 로 맞춘다. 4 MB 롬(SvC) 상위 뱅크는 CPU−0x600000. tile_base 는 겹마다 다르다(R-2 앞 64·뒤 183).
- C 형: 지도 행이 VRAM 행과 그대로 같다(FC 평면2 0x07FFB1 20×16). 타일은 색인 순 연속이라 «로고가 쓰는 색인 범위»가 예산.
- 팔레트 표를 롬에서 못 찾으면 .pal 덤프(스크롤1 0x80·스크롤2 0x100)를 쓴다. 팔레트 값에 비트13(16~31)이 섞여도 화면은 하위 4비트.

| 게임 | 형식 | 기록 | 그림 | 타일 | 예산 | 팔레트 | 비고 |
|---|---|---|---|---|---|---|---|
| 아랑 FC (JUE) | C | 평면2 지도 0x07FFB1 (행 3~11 이 로고) | 20×16 | 0x07E493+16·idx (색인 1~99) | 99 | 스크롤2 0·1·2·4~8 | 평면1 0x080371 = 벽돌 배경 |
| KOF R-2 (JUE) | B ×2 | 앞 0x02B986 (cnt 119, ptr 0x0149C6, +64) · 뒤 0x02BC8A (cnt 63, ptr 0x0155D6, +183) | 20×19 | 연속 | 119 / 63 | 앞 0·8·9·10 · 뒤 0·1·8·9·10 | 화면 x+24 스크롤. 형제 «14 13» 25개 |
| SvC (JUE) | B | 0x38637E (cnt 215, ptr 파일 0x306CE0, +64) | 20×19 | 연속 | 215 | 0~15 | 배경 = 0x386074. 형제 76개 |
