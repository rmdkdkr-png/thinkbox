**규칙 셋 — 어기면 헛수고다**

3. **장면은 판정기 하나로 고르지 마라**(traps ⑫). `endpick.isend()` 는 «좌우 갈색 체크 테두리 + 가운데 80% 이상 검정»으로 엔딩 글 페이지만 고른다 — 카드·스태프롤·어두운 무대가 전부 걸러진다.

## 카드 (2026-09-05)
```
python3 cardshot.py <시작> <끝> [폴더]        # 번호로 앞면 f###.png · 설명면 d###.png
python3 cardaudit.py <롬.ngc> [이름]          # 120장 찍고 재고 «사람이 볼 것»만 골라 낸다
python3 cardaudit.py --measure <찍은폴더> [이름]
python3 popupcap.py <자리> [표본수]           # 카드 획득 팝업(런 끝에 나온다)
```
**함정 넷**
1. **누름은 8프레임.** 4프레임이면 방향키가 폴링 사이로 새서 목록 커서가 한 칸도 안 움직인다.
2. **설명면에서 A 한 번이면 곧바로 목록**이다(앞면을 건너뛴다). 두 번 누르면 컬렉션 밖으로 나간다.
3. **줄마다(8장) 찬 부팅**으로 끊는다 — 한 번에 120장을 돌리면 누름 하나가 새는 순간 뒤가 전부 어긋난다.
4. **글 상자 안쪽은 y 24~131 이다.** y 134~140 은 No·별 줄이라, 거기까지 세면 **모든 카드가 한 줄 더 있는 것으로 나온다**(내가 한 번 틀렸다 — 현행 최대는 8줄이 아니라 7줄).

**«빠진 글자»는 화면만으로 못 잡는다.** 띄어쓰기가 8 px 라 「가운데 빈 칸」 판정은 정상 문장에도 다 걸린다(120장 전부 걸렸다).
대신 `cardaudit` 이 **글자 칸 수**를 세어 주니 그것을 글 담당의 글자 수와 **번호로 맞대는** 것이 진짜 검사다.
깨진 타일은 **«한 칸이 70% 넘게 찬다»**로 잡는다(정상 한글은 25~45%).

### 글 표와 맞대기 (cardaudit)
`CARDS_CENSUS`(기본 `~/ss2/work_lang/v10/review/census/cards_counts_for_audit.tsv`)가 있으면 **기대칸·차이** 열이 붙는다.
관계는 실측으로 잡았다 — **화면 칸 수 ≈ 글자 + 아이콘 + 줄수**. 배포본(멀쩡한 롬)에서 잔차는 **−5 ~ +3** 안에 들어온다.
그래서 **−8 ~ +6 밖이면 ★칸수차**로 잡는다. **줄 하나가 통째로 빠지면(약 11칸) 반드시 걸린다.**
⚠ 한 글자만 빠진 것은 이 방법으로 못 잡는다 — 화면 글자 폭이 고르지 않아 셈이 ±몇 칸 흔들린다. 「글자 수가 정확히 맞나」는 롬 쪽 표로 봐야 한다.

### 제목 기준 (2026-09-05 정정)
명판 **안쪽은 85 px** 이지만 **글자가 놓이는 곳은 칸 10개 = 80 px(x 40~119)** 다. 안전선은 78.
`cardaudit` 은 여백을 **그 80 px 기준**으로 잰다 — 85 로 재면 78~80 짜리가 「여유 있음」으로 새어 나간다.
· **★글자칸넘침** = 잉크가 x 40~119 밖으로 나갔다 · **△빠듯** = 좌·우 여백 0(더 못 늘린다).
· 훑는 범위 자체는 명판 안쪽 x 38~122 로 둔다 — 더 넓히면 **명판 테두리의 밝은 화소가 잉크로 잡혀 120장이 전부 걸린다**(한 번 그렇게 틀렸다).
